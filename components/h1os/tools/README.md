# H1OS Developer Tooling & Packaging Suite

This directory contains the developer tooling, packaging, size auditing, and flashing infrastructure for H1OS on ESP32-S3.

---

## 1. Architecture

The H1OS developer tooling employs a three-tier architecture:

```text
+-----------------------------------------------------------------------+
|  User Entry Points                                                    |
|  - idf.py h1os_menu / h1os_pack / h1os_size / h1os_flash / h1os_erase |
|  - python components/h1os/tools/menu/h1os_menu.py (Rich Console UI)   |
|  - python components/h1os/tools/h1os_tool.py <subcommand>             |
+-----------------------------------------------------------------------+
                                   |
                                   v
+-----------------------------------------------------------------------+
|  Configuration & Validation Layer (h1os.ini)                          |
|  - Strictly validated by H1OSConfig                                   |
|  - Zero Guesswork / Zero Fallbacks: Missing keys fail immediately     |
+-----------------------------------------------------------------------+
                                   |
       +---------------------------+---------------------------+
       |                           |                           |
       v                           v                           v
+---------------+          +---------------+          +-----------------+
|  h1os_pack.py |          |  h1os_size.py |          |   esptool.py    |
|  Bundler      |          |  Audit Engine |          |  Flash / Erase  |
+---------------+          +---------------+          +-----------------+
```

## 2. Configuration (`h1os.ini`)

`h1os.ini` is located in the application project root (e.g. `examples/H1OS/h1os.ini`). It is automatically provisioned by CMake from `components/h1os/h1os.ini.template` if absent.

```ini
[project]
# Base application directory relative to this file (default: .)
project_dir = .
# Optional explicit application binary name (e.g. h1os.bin)
app_name = 

[build]
# Build directories for development and production profiles
build_dir_dev = build_dev
build_dir_prod = build_prod
# Target output folder for release bundles and standalone binaries
dist_dir = dist
# Optional release bundle naming prefix/suffix:
# e.g. pack_prefix_prod = prod_   -> prod_2.4.7-dev.zip
#      pack_prefix_dev  = debug_  -> debug_2.4.7-dev.zip
pack_prefix = 
pack_suffix = 
pack_prefix_prod = prod_
pack_prefix_dev = debug_

[audit]
# Destination directory for production size audit diagnostic logs (required for prod size audit)
prod_build_audit_log = build_prod/logs

# Destination directory for development size audit diagnostic logs (required for dev size audit)
dev_build_audit_log = build_dev/logs

[version]
# Explicit semantic version override (e.g. 2.4.7)
version = 
# File to extract version from (relative to project_dir or component root)
version_file = ../../components/h1os/include/h1os/h1os_version.h
# Regular expression with exactly one capture group to parse the version
version_regex = #define\s+H1OS_VERSION_STRING\s+"([^"]+)"

[partitions]
# Custom partition table CSV path (defaults to standard partitions.csv in project root)
partition_file_location = partitions.csv

[target]
# Target silicon chip (passed to esptool --chip)
chip = esp32s3
# Serial port for flashing/erasing (leave blank for esptool auto-discovery, or specify e.g. COM3)
port = 
# Flashing communication baud rate
baud = 460800
```

### Zero-Fallback Policy
* **Audit Log Destinations**: If `prod_build_audit_log` or `dev_build_audit_log` is omitted or empty when running a size audit on that build, `h1os_size` halts immediately with exit code `1` (no synthetic directory defaults).
* **Partitions Table**: If `partitions.csv` is not present in the project root or configured path, tools fail immediately with exit code `1` (no synthetic fallback strings).
* **Version Extraction**: If the configured regex does not match in `version_file`, tools fail immediately with exit code `1` (no hardcoded fallback strings).
* **Build Artifacts**: Missing build directories or application binaries produce actionable errors on `stderr`.
* **Single Source of Truth for Flash Parameters**: Compiled SPI flash configuration (`flash_mode`, `flash_freq`, `flash_size`, and partition offsets) resides strictly in `<build_dir>/flash_args` generated by ESP-IDF CMake from `sdkconfig` and `partitions.csv`.

## 3. Interactive Rich Console (`h1os_menu.py`)

Launch the interactive console:
```powershell
idf.py h1os_menu
# or directly:
python components/h1os/tools/menu/h1os_menu.py -C examples/H1OS
```

Features:
* Real-time keyboard navigation with arrow keys (`UP`, `DOWN`, `ENTER`, `1`–`7`, `Q`/`ESC`).
* Layout clamped to 78 columns for narrow terminals.
* Explicit flashing options for both Production and Development builds.
* Clean visual cues with 0 third-party branding.
* Full compatibility with standard ESP-IDF v6.1 virtual environment (`rich` 15.0.0).

## 4. Master Dispatcher CLI (`h1os_tool.py`)

The headless engine can be driven via standard command-line arguments:

```powershell
# Package production release bundle
python components/h1os/tools/h1os_tool.py -C examples/H1OS pack -B examples/H1OS/build_prod

# Package development release bundle
python components/h1os/tools/h1os_tool.py -C examples/H1OS pack -B examples/H1OS/build_dev

# Inspect binary size and memory headroom (writes to configured audit log directory)
python components/h1os/tools/h1os_tool.py -C examples/H1OS size -B examples/H1OS/build_prod
python components/h1os/tools/h1os_tool.py -C examples/H1OS size -B examples/H1OS/build_dev

# Flash target hardware via esptool write-flash
python components/h1os/tools/h1os_tool.py -C examples/H1OS flash -B examples/H1OS/build_prod

# Erase entire flash die via esptool erase-flash
python components/h1os/tools/h1os_tool.py -C examples/H1OS erase
```

## 5. ESP-IDF CLI Extensions (`idf.py`)

All tools are registered as first-class extensions in `idf.py`:

| Command | Aliases | Description |
| :--- | :--- | :--- |
| **`idf.py h1os_menu`** | `menu`, `tools`, `tools-menu` | Launches the interactive Rich console. |
| **`idf.py h1os_tool`** | `h1os`, `tool` | Headless dispatcher forwarding subcommands. |
| **`idf.py h1os_pack`** | `pack`, `release`, `h1os-release` | Release packager (`--no-zip`, `-V`, `--prefix`, `--suffix`). |
| **`idf.py h1os_size`** | `size-audit`, `h1os-size` | Deep binary size and partition headroom audit. |
| **`idf.py h1os_flash`** | `flash-now` | Flashes firmware using `esptool write-flash`. |
| **`idf.py h1os_erase`** | `erase-chip` | Scrubs full 8 MB flash using `esptool erase-flash`. |
| **`idf.py monitor-ts`** | - | Serial monitor with line-by-line timestamps. |
