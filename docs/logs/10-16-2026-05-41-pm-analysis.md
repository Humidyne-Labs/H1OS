## 1. Hardware Log Observations & Root Cause Analysis

### Observation 1: ULP Wake Telemetry & Hold Latency
- **Log Trace:**
  ```text
  I (1731) h1os_lifecycle: [ULP TELEMETRY] Wake #2: cause=1 (RTC_GPIO_INT), rtcio_raw=0x000001, btn=1, hold=2960 ms, samples=297, cycles=51960582
  ```
- **Reviewer Comment:**
  *"this is messed up, if it was realy an int event, it took way too long to wake the ulp."*
- **Root Cause:**
  1. GPIO 0 (`BOOT0`) has no external pull-up resistor on the Waveshare board. In `components/h1os/ulp/main.c`, `ulp_riscv_gpio_init(GPIO_NUM_0)` sets RTC MUX selection but does NOT call `ulp_riscv_gpio_pullup(GPIO_NUM_0)`.
  2. When the user pressed and released the tactile button, without an active pull-up, the pin remained capacitively held near ground (LOW) across 297 loop iterations ($2960\text{ ms}$) until reaching the 3.0s boundary.
  3. The architecture requires: Wake ULP via IO event $\rightarrow$ ULP polls IO $\rightarrow$ ULP wakes main app.
- **Resolution:**
  - Call `ulp_riscv_gpio_pullup()` for GPIO 0, 18, and 5 in the ULP.
  - Implement responsive release detection: poll pin every 10 ms; upon reading HIGH and confirming release (5 ms debounce), immediately break out, latch actual tap duration ($< 150\text{ ms}$), and trigger `ulp_riscv_wakeup_main_processor()`.

### Observation 2: MicroSD Initialization Timeout & Thrashing
- **Log Trace:**
  ```text
  D (9853) SD_TRANS: process_command_response: error 0x107 (status=00000104)
  ...
  E (10514) vfs_fat_sdmmc: sdmmc_card_init failed (0x107).
  D (10564) sub_sdcard: Asynchronous MicroSD mount failed: ESP_ERR_TIMEOUT (no card inserted or unformatted)
  ```
- **Reviewer Comments:**
  *"still trying to init sd, preflight failed."*  
  *"time out means init prior to io check."*
- **Root Cause:**
  1. The PCB has physical external $10\,\text{k}\Omega$ pull-up resistors on DAT0 (GPIO 40) and CMD (GPIO 41). The internal pull-down electrical probe in `sub_sdcard_probe()` therefore always reads logic HIGH ($2.7\,\text{V}$), returning a false positive card detection.
  2. Because `app_on_wake()` called `sub_sdcard_mount_async()` on every button wake, the system incurred a 1-second ACMD41 timeout and driver error dump on every wake.
- **Resolution:**
  - Latch card absence on cold boot (`s_card_absent_latched = true`) if the card does not respond.
  - Skip subsequent mount attempts on deep-sleep wake sessions if no card was present.
  - Silence `SD_HOST`, `SD_TRANS`, and `vfs_fat_sdmmc` log tags via `esp_log_level_set()`.

### Observation 3: LEDC Driver Log Spam
- **Log Trace:**
  ```text
  D (11942) ledc: duty_config: duty-0, dir-1, cycle-4, scale-1, step-1023
  D (12942) ledc: duty_config: duty-1023, dir-0, cycle-4, scale-1, step-1023
  ```
- **Reviewer Comment:**
  *"ledc spam, idk if internal log, our if were doing it."*
- **Root Cause:**
  - ESP-IDF's `ledc_duty_config()` in `esp_driver_ledc/src/ledc.c` emits `ESP_EARLY_LOGD()`.
  - In `sdkconfig.defaults.dev`, `CONFIG_LOG_DEFAULT_LEVEL_DEBUG=y`. Per user directive, **default sdkconfigs must remain untouched**.
- **Resolution:**
  - ESP-IDF's `ESP_EARLY_LOGD` evaluates `esp_log_get_default_level()`.
  - In early initialization, set runtime default log level to `ESP_LOG_INFO` via `esp_log_level_set("*", ESP_LOG_INFO)` while explicitly elevating all H1OS application component tags to `ESP_LOG_DEBUG`. This silences internal driver `ESP_EARLY_LOGD` noise while preserving all application debug logging.
