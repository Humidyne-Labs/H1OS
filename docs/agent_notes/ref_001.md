
## Q3
does this need a return check? ulp_riscv_gpio_isr_register
### Answer
Yes — you should check it. `ulp_riscv_gpio_isr_register` returns `esp_err_t` and has three real failure paths, so ignoring it can silently leave you with no handler registered. esp-idf:11-30 

---

## What can fail

| Condition | Return value |
|---|---|
| `gpio_num < 0` or `>= GPIO_NUM_MAX` | `ESP_ERR_INVALID_ARG` |
| `intr_type` out of range (`>= ULP_RISCV_GPIO_INTR_MAX`) | `ESP_ERR_INVALID_ARG` |
| `handler == NULL` | `ESP_ERR_INVALID_ARG` |
| Handler slot already allocated (via `ulp_riscv_intr_alloc`) | `ESP_ERR_NOT_FOUND` | esp-idf:13-29 esp-idf:31-48 

The last case matters: the function calls `ulp_riscv_intr_alloc(ULP_RISCV_RTCIO0_INTR_SOURCE + gpio_num, ...)`, which returns `ESP_ERR_NOT_FOUND` if that per-pin slot already has a handler — e.g., if you register twice without calling `ulp_riscv_gpio_isr_deregister()` first. esp-idf:28-35 

## Caveats

- Note the ordering quirk: the interrupt *type* is written to `RTC_GPIO_PIN0_INT_TYPE` **before** `ulp_riscv_intr_alloc` is called, so a failure can leave the pin configured for an interrupt type with no handler behind it. esp-idf:25-29 
- This API only exists when `CONFIG_ULP_RISCV_INTERRUPT_ENABLE` is set. esp-idf:110-133 
- Checking the return is especially worthwhile here because the ULP RISC-V has no `printf`/JTAG debugging — a silently failed registration is hard to diagnose, which is why the docs recommend shared variables or the bit-banged UART for observability. esp-idf:308-317

esp_err_t ulp_riscv_gpio_isr_register(gpio_num_t gpio_num, ulp_riscv_gpio_int_type_t intr_type, intr_handler_t handler, void *arg)
{
    if (gpio_num < 0 || gpio_num >= GPIO_NUM_MAX) {
        return ESP_ERR_INVALID_ARG;
    }

    if (intr_type < 0 || intr_type >= ULP_RISCV_GPIO_INTR_MAX) {
        return ESP_ERR_INVALID_ARG;
    }

    if (!handler) {
        return ESP_ERR_INVALID_ARG;
    }

    /* Set the interrupt type */
    REG_SET_FIELD(RTC_GPIO_PIN0_REG + 4 * gpio_num, RTC_GPIO_PIN0_INT_TYPE, intr_type);

    /* Set the interrupt handler */
    return ulp_riscv_intr_alloc(ULP_RISCV_RTCIO0_INTR_SOURCE + gpio_num, handler, arg);
}

esp_err_t ulp_riscv_gpio_isr_deregister(gpio_num_t gpio_num)
{
    return ulp_riscv_intr_free(ULP_RISCV_RTCIO0_INTR_SOURCE + gpio_num);
}

----------------------------------

When programming the ULP RISC-V, it can sometimes be challenging to figure out why the program is not behaving as expected. Due to the simplicity of the core, many of the standard methods of debugging, e.g., JTAG or ``printf``, are simply not available.

Keeping this in mind, here are some ways that may help you debug your ULP RISC-V program:

 * Share program state through shared variables: as described in :ref:`ulp-riscv-access-variables`, both the main CPU and the ULP core can easily access global variables in RTC memory.  * Use the bit-banged UART driver to print: the ULP RISC-V component comes with a low-speed bit-banged UART TX driver that can be used for printing information independently of the main CPU state. See :example:`system/ulp/ulp_riscv/uart_print` for an example of how to use this driver.

## Q4
does the handler persist across riscv runs?
### Answer
## Short answer

Mostly yes — the handler table `s_intr_handlers` is ordinary RAM data inside the ULP binary (which lives in RTC memory), not hardware state, so it survives as long as that memory isn't re-initialized. But each fresh program start runs the startup code (`reset_vector` → `__start` in `ulp_riscv_vectors.S`), and if `.bss` is re-zeroed there, the table is wiped — so the safe pattern is to (re-)register during init each run and treat `ESP_ERR_NOT_FOUND` as "already registered." esp-idf:28-29 esp-idf:69-71 

---

## What's persisted where

| State | Where it lives | Persists across runs? |
|---|---|---|
| Handler + arg | `s_intr_handlers[]` — static array in ULP program's data (RTC RAM) | Yes, unless `.bss`/data re-initialized on start |
| GPIO interrupt *type* | `RTC_GPIO_PIN0_INT_TYPE` hardware field (RTC domain) | Yes — survives deep sleep and halts until rewritten |
| IRQ vector → `_ulp_riscv_interrupt_handler` | Fixed code path | Always |

- Registration is purely a software write into `s_intr_handlers[source]` — nothing is programmed into hardware except the GPIO `INT_TYPE` field done earlier in `ulp_riscv_gpio_isr_register`. esp-idf:25-29 
- Because `ulp_riscv_intr_alloc` rejects an occupied slot with `ESP_ERR_NOT_FOUND`, you can probe persistence: a second `ulp_riscv_gpio_isr_register` for the same pin will fail if the old registration survived. esp-idf:38-47 
- The dispatcher reads this table every IRQ (SW interrupts → `ULP_RISCV_SW_INTR_SOURCE`, RTC IO → `ULP_RISCV_RTCIO0_INTR_SOURCE + pin`), so as long as the array content survives, dispatch works with no re-registration needed. esp-idf:71-105 

## Caveat

Whether `.bss` is cleared on every restart depends on the ULP startup code path after `reset_vector`, which isn't in the retrieved snippets — so I can't state definitively for your target whether a halted-and-restarted program re-initializes the table. esp-idf:65-71  The idiomatic pattern (and what the `ulp_riscv/interrupts` example does) is to register handlers once during program init before the main loop — that works correctly under both behaviors. Note this is all on the **ULP side**; the separate `ulp_riscv_isr_register()` on the *main* CPU (`RTC_CNTL_COCPU_INT_ST_M`/`TRAP_INT_ST_M`) is a normal RTC ISR and is unrelated to this question. esp-idf:35-57

 * - Checks if one or more RTC IO interrupt status bits are set
 * - Calls the interrupt handler for the RTC IO if it is registered
 * - Clears all interrupt bits

{
    uint32_t handler_idx = 0;

esp_err_t ulp_riscv_isr_register(intr_handler_t fn, void *arg, uint32_t mask)
{
    /* Verify that the ISR callback is valid */
    ESP_RETURN_ON_FALSE(fn, ESP_ERR_INVALID_ARG, TAG, "ULP RISC-V ISR is NULL");

    /* Verify that the interrupt bits are valid */
    if (!(mask & (RTC_CNTL_COCPU_INT_ST_M | RTC_CNTL_COCPU_TRAP_INT_ST_M))) {
        ESP_LOGE(TAG, "Invalid bitmask for ULP RISC-V interrupts");
        return ESP_ERR_INVALID_ARG;
    }

    /* Make sure we enable only the  ULP interrupt bits.
     * We don't want other RTC interrupts triggering this ISR.
     */
    mask &= (RTC_CNTL_COCPU_INT_ST_M | RTC_CNTL_COCPU_TRAP_INT_ST_M);

    /* Register the RTC ISR */
    ESP_RETURN_ON_ERROR(rtc_isr_register(fn, arg, mask, 0), TAG, "rtc_isr_register() failed");

    /* Enable the interrupt bits atomically to avoid race condition with other code accessing RTC_CNTL_INT_ENA_REG */
    RTC_CNTL_ATOMIC() {
        SET_PERI_REG_MASK(RTC_CNTL_INT_ENA_REG, mask);
    }
