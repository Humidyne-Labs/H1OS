# H1OS Historical Engineering Digest & Archive Summary

> **Document Status:** Authoritative Historical Digest  
> **Target Hardware:** Waveshare ESP32-S3 ePaper 1.54" V2 (`ESP32-S3-PICO-1-N8R8`)  
> **Purpose:** Consolidated summary and essential engineering takeaways distilled from legacy reference documents, historical audits, and experimental action plans prior to H1OS v2.0+ architecture.

---

## 1. Overview & Purpose

During early board bring-up and driver prototyping (v1.0.0 through v1.3.1), several architectural plans, power profiling notes, font conversion experiments, and code audits were authored. To keep the active repository concise, clean, and cohesive, the original archive files have been retired. 

This digest preserves the critical technical rationale, empirical findings, and physics-based models that inform current H1OS development.

---

## 2. Summaries & Key Engineering Takeaways

### 2.1 Early 3-Tier Architecture (`docs/archive/ARCHITECTURE.md`)
- **Summary:** Documented the early three-tier system partition separating the demo application (`Unified_BSP_Demo`), BSP core components (`components/esp32-s3_bsp`), and underlying ESP32-S3 hardware subsystems.
- **Current Takeaway:** While superseded by the canonical 4-layer H1OS structure (Layer 1 HAL, Layer 2 Subsystems, Layer 3 Orchestrator, Layer 4 API), this document originated the strict isolation between physical sensor acquisition and business logic, FreeRTOS task prioritization (LVGL on Core 1 priority 4, audio worker priority 5), and the zero-copy display refresh pipeline.

### 2.2 Legacy Doxygen API Documentation (`docs/archive/api.md`)
- **Summary:** An autogenerated 288 KB Doxygen reference documenting early `bsp_*` structs (`bsp_config_t`, `bsp_app_lifecycle_t`, `bsp_shtc3_data_t`) and function prototypes.
- **Current Takeaway:** Retained for reference during migration to the unified `h1os_*` naming convention. All legacy APIs (`bsp_common_*`, `bsp_sensors_*`) have been consolidated into clean Layer 4 headers (`h1os.h`, `h1os_lvgl.h`, `h1os_time.h`).

### 2.3 Bilevel 1-Bit Font Conversion & Inversion Dynamics (`docs/archive/epaper_1bit_font_inversion_guide.md`)
- **Summary:** Explores why anti-aliased 4-bpp grayscale fonts experience perimeter erosion when rendered inverted (white text on black background) on 188 DPI electrophoretic displays.
- **Current Takeaway:** In 4-bpp anti-aliasing, semi-transparent edge pixels thresholded at $\ge 128$ snap to white (background in inverted mode), eroding letter stems inward by 1 pixel per edge. On fine fonts, this collapses glyphs into broken dots. H1OS mitigates this by generating 1-bpp bilevel Montserrat bold fonts using `--autohint-strong` and `--bpp 1`, ensuring symmetric dilation, 50% flash savings, and instant bit-blitting without renderer interpolation. Inverted text blocks are now utilized intentionally for the top-right interactive session badge to visually signal awake vs unattended sleep state.

### 2.4 ULP-RISC-V Coprocessor Bring-Up Guide (`docs/archive/ulp_riscv_guide.md`)
- **Summary:** Detailed early instructions for compiling and embedding RV32IMC assembly and C code into the ESP32-S3 RTC Slow Memory domain (`0x5000_0000` to `0x5000_1FFF`).
- **Current Takeaway:** Served as the foundation for Layer 3 ULP engineering. The earlier polling design has evolved into H1OS's event-driven, interrupt-reactive ULP Monitor that avoids bus contention while Xtensa executes Flow B sessions, with wake intervals configured dynamically by the developer.

### 2.5 VS Code & ESP-IDF Toolchain Environment (`docs/archive/VSCODE_ESP_IDF_GUIDE.md`)
- **Summary:** Setup walk-through for Visual Studio Code, CMake, and the Espressif IDF extension across ESP-IDF v5.1 through v6.1.
- **Current Takeaway:** Standardized our recommended toolchain configuration, `c_cpp_properties.json`, compile commands database, and Express installation paths for the `xtensa-esp32s3-elf` toolchain.

### 2.6 Early Modernization Action Plan (`docs/archive/dev-action/ACTION_PLAN.md`)
- **Summary:** Outlined multi-phase modernization covering ES8311 audio bring-up, fast RTC Wi-Fi cache reconnection, SNTP synchronization to the PCF85063A RTC, and ThingsBoard IoT provisioning.
- **Current Takeaway:** Defined the separation of network services from hardware HAL. ThingsBoard telemetry schemas and RTC calibration sequences developed here remain active reference patterns.

### 2.7 ULP Cooldown Gating & Ring Buffer Model (`docs/archive/dev-action/gated-model.md`)
- **Summary:** Defined an integer fixed-point comparator model in RTC Slow Memory to gate sensor readings until thermal equilibrium is established ($dT/dt \le 0.15^\circ\text{C}$).
- **Current Takeaway:** Because the ULP-RISC-V core lacks a floating-point unit (FPU), temperatures are stored as centi-degrees Celsius ($1^\circ\text{C} = 100\text{ units}$). This integer math foundation is embedded in `orch_math.c` and shared RTC structs.

### 2.8 Deep Sleep Hardware Power Profiling (`docs/archive/dev-action/hardware-notes.md`)
- **Summary:** Comprehensive current measurements across power rails and component sleep states, including quiescent drains for the ETA6098 charger and MP1605 buck regulator.
- **Current Takeaway:** 
  - ESP32-S3 Deep Sleep (RTC slow memory retained, ULP halted): $\sim 7.0\,\mu\text{A}$.
  - ES8311 Audio Codec (Software Power-Down register `0x0D`): $< 1.0\,\mu\text{A}$.
  - PCF85063A RTC (CLKOUT disabled `COF[2:0] = 111`): $\sim 0.22\,\mu\text{A}$.
  - SSD1681 Display (Deep Sleep Mode 1 `0x10, 0x01`): $\sim 1.0\,\mu\text{A}$.
  - SHTC3 Sensor (Sleep command `0xB098`): $\sim 0.3\,\mu\text{A}$.
  - Estimated total quiescent floor from battery ($V_{\text{BAT}} = 3.7\,\text{V}$): **$21\,\mu\text{A} \dots 28\,\mu\text{A}$** with buck converter idling.
  - Critical firmware rule: SSD1681 `CS` and `RST` must be latched HIGH prior to sleep using RTC pad hold to prevent back-powering via digital protection diodes.

### 2.9 Tri-Node Sensing & Psychrometric Foundation (`docs/archive/dev-action/HUMIDITRON_TRI_NODE_ULP_ACTION_PLAN.md`)
- **Summary:** Introduced the physical explanation of PCB thermal drift and established the Tri-Node Psychrometric architecture.
- **Current Takeaway:** 
  - PCB self-heating warms the sensor die via copper trace conduction ($T_{\text{die}} > T_{\text{air}}$), which inflates saturation vapor pressure $e_s(T_{\text{die}})$ and depresses measured relative humidity ($RH$).
  - Actual water vapor pressure ($e$) and Dew Point ($T_{\text{dew}}$) are thermodynamic invariants.
  - Tri-node cross-correlation combines: Node 1 (SHTC3 ambient), Node 2 (SSD1681 on-glass thermistor via SPI Command `0x1B`), and Node 3 (ESP32-S3 TSENS on-chip silicon).

### 2.10 Low-Power Application Prototype Outline (`docs/archive/dev-action/new-project-outline-low-power-test.md`)
- **Summary:** Concept notes for a cyclic deep-sleep demo displaying metrics on e-paper, handling battery auto-cutoff at 5–10%, and investigating MicroSD card sleep leakage.
- **Current Takeaway:** MicroSD cards lack an external high-side power gate on this PCB and draw an estimated $300\,\mu\text{A} \dots 800\,\mu\text{A}$ at idle, highlighting why the MicroSD card must be unmounted and avoided during low-power battery cycles.

### 2.11 Historical v1.3.1 Features & Codebase Audit (`features-to-date.md` & `VERSION_1.3.1_CODE_AUDIT.md`)
- **Summary:** Comprehensive audit across the codebase prior to the H1OS v2.0 restructuring, tracking verified drivers against backlog items and identifying architectural coupling and naming inconsistencies.
- **Current Takeaway:** Established the remediation roadmap that produced the four-layer architecture, removed dead sensor calibration hacks, and standardized pad latching.
